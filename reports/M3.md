# M3: the AV-IDS v3 system, end to end on streams (milestone report)

Date: 2026-10-25    Source: reports/WP7_S2.md; numbers: results/WP7/S2_acceptance.json, S2_results.json, S2_tables.md.    **Verdict: NOT MET** (8 of 12 pre-registered rows; the four failures are the alert rate, the false-alarm rate, the mean detection and the SAFE_STOP rate on comma).

## 1 What the system does
- **Five detection domains** with frozen outputs, each a stack of physics / rule layers plus normal-only models, label-free combiner, calibrated per domain at a 1% false-alarm budget (M1 reports, all closed PARTIAL):
  - GPS (gps/domain.py, 16 layers: dead reckoning, rules, EKF, CUSUM, LiDAR-odometry residual);
  - CAN (can/domain.py, ROAD: specification rules, per-signal predictors, reverse-light rule);
  - LiDAR (lidar/domain.py: ring geometry, object intensity, background model, tracking; max of four ranks, 1% scan budget);
  - network (network/domain.py, stack H, topology-free: scan, brute force, TCP flags, random walk);
  - V2X (physics-only stack, 12 checks; calibrated on VeReMi, which is unusable on real traffic until recalibrated per deployment: 92-95% false alarms became ~1% with per-deployment calibration, M1-V2X addendum).
- **Cross-domain layer** (WP6): GPS / IMU, LiDAR odometry and CAN wheel speed observe the same ego motion; normalised residuals give a pairwise test and a "which domain lies" blame.
- **Fusion** (fusion/system.py `load_system(2)`): per-entry density transform and ECDF, log-form noisy-or (label-free), system threshold at 2% of clean ticks, temporal correlator (alert event = 2 alarms in 5 s, merge within 15 s), blame by decided majority, response policy (WARN, DEGRADE the blamed domain, SAFE_STOP recommendation needing two domains with their own alarm, V2X / network never above DEGRADE), every event explained.
- **Runtime** (WP7): one runner per domain (sample in, Evidence out, latency log), an Evidence bus, a 1 Hz FusionRunner that sees a tick only when its Evidence has arrived (the network Evidence of a flow arrives when its 5-minute bin has closed).

## 2 How it was tested, and the limit of the test
No public dataset has all five domains on one car. Every composite puts each domain's own TEST stream on a common clock; correlations between domains are constructed, except inside the vehicle block (KITTI: GPS, IMU, LiDAR and a simulated CAN wheel speed of the same car; comma2k19: real GNSS, CAN speed, gyro). Persistent attacks start at tick 3 of the block. All test episodes are used (no random subset): 213,744 attack composites of 134 types, 16 + 16 clean timelines of 7.93 h each (the D10 clean blocks as backbone, so the network runs for hours). Domain streams: 4.0 M CAN frames, 709,430 V2X messages, 585,951 flows, 13,024 LiDAR scans, GPS / witness streams. Exposure: 5th scoring of fusion test data, nothing tuned, one run. Stream equals batch: 213,776 composites, 0 mismatches; 6 composites driven live through all runners, 0 mismatches.

- By attacked domain (K, event detection, median seconds until the alarm is visible): V2X 76.8% (4 s), GPS 69.6% (7 s), network 93.3% (120 s: the 5-minute bin plus the minute hold, 66 s median Evidence delay, 242 s max), CAN 45.5% (4 s), cross-only motion-sensor spoofs 32.1% (12 s), LiDAR 9.5% (4 s).
- Response: 89.0% of detected K single-domain events reach DEGRADE (the blamed domain is distrusted: GPS falls back to LiDAR / wheel odometry, CAN speed to GNSS / IMU, V2X messages are dropped, the network host is isolated), 0.08% SAFE_STOP.
- Coordinated attacks: GPS + CAN spoof on the KITTI car is detected 71.4% but blamed on the honest sensor 70% (the witnesses agree); on comma 100% detected and correctly blamed; a ROAD CAN attack together with a GPS attack (11 composites) is detected 11 of 11, with PointDrop 10 of 11.
- **What does not work**: single-return LiDAR phantoms are at chance (3.6% per scan, 0.6% for 3 s persistent episodes; a single-return sensor cannot show a phantom as a duplicate return); comma GNSS spoofs are blamed on the wrong domain (0% correct for drift, meaconing, doppler); the alert rate is far from a deployable one; false alarms of the validation calibration do not transfer to test (S5b: validation 2.1%, test 3.5%).
- Design variant, not the headline: if the corroborating second domain for SAFE_STOP must be GPS, LiDAR, CAN or cross-domain (V2X / network excluded), C clean SAFE_STOP falls from 1.64 to 0.63 per hour [0.0, 0.93]; K is unchanged. It was fixed a priori but adopting it now would be informed by test, so it stays a variant.

## 4 Real-time feasibility (this shared machine, one core per domain)
| domain | cost | keeps up? |
|---|---|---|
| GPS | 58.5 ms per fix (p99 137 ms), period 1 s | yes |
| cross-domain | witness step p99 16 ms | yes |
| CAN | 4 us per frame; 0.14 s per window below 100k frames in the capture, 2.3 s above 600k frames (prefix re-score) | frames yes; windows fail on long captures |
| network | 1.2 ms per flow, stall 1.4 s median / 7.7 s max at each bin close | yes on average, Evidence 66-242 s late by design |
| V2X | 41 ms per message; the whole-block stream of all senders needs 1.9 compute s per stream s; one ego hears 7.4 messages/s | whole stream no, one ego plausible (not validated) |
| LiDAR | 1.98 s per scan on a lightly loaded machine (3.98 s under the pass load), period 0.103 s | **no**: 19x too slow (about 20 cores for real time) |
| fusion | 0.36 ms per tick | yes |
The GPS, CAN and V2X runners re-score the prefix of the stream with the frozen batch code (no incremental entry point), which is why their cost grows with the stream; an incremental version is a proposal, not done.

## 5 Where this leaves v3
- Each domain is a documented detector with an honest operating point (M1 reports, all PARTIAL); the system around them is built, frozen, explained and runs as streams; it is not deployable: too many alerts per hour, a LiDAR that cannot run in real time on this machine, and no dataset that proves the cross-domain claim on a real five-domain car.
- v2's simulation (91.67% accuracy, 1.90% false alarms on 7,800 rows) is not comparable (single rows, supervised meta-classifier on the classes it was tested on, multi-return LiDAR attacks a real sensor cannot produce, long blocks, random halves). On v2's own view v3 is not better.
- The claim the data support: physics / rule layers and normal-only models are complementary (held-out types 71% for the fused system); the cross-domain layer adds a second kind of evidence for motion-sensor spoofs; it does not lower the alert rate.

## 6 Limits
Constructed composites; comma witnesses aligned upstream (cross layer streamed per second on residual rows); no network Evidence in short composites (long network blocks instead); VeReMi has no receiver positions (ego view = the M2 construction); the V2X detector is calibrated on simulation; GPS-LiDAR coupling not re-run; timing under load; the 18-27 events per hour come from small validation pools (3 KITTI drives, 10 clean ROAD captures); live check has events in 2 of 6 composites.
