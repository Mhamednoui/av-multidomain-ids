# M2: cross-domain consistency + system fusion (AV-IDS v3) - LiDAR INTERIM

Date: 2026-10-24    WP6 S1-S5 (worker opus, T4; S4 sonnet)    Proposed verdict: **PARTIAL** (system built, frozen, explained; FA / alert-rate targets NOT met)
Sources: reports/WP6_S1..S5.md, results/WP6/s3_*, s4_*, s5_* (tables: s5_tables.md). All numbers below are copied from those files.

## 1 What the M2 system is
Five frozen domains plus one cross-domain layer feed one label-free fusion on a 1 Hz clock. The fused alarms then go through a temporal correlator and a response policy.
- **Domains (frozen M1 outputs):**
  - GPS: gps/domain.py.
  - CAN: can/domain.py, ROAD.
  - Network: network/domain.py, stack H, the view of one host in D10.
  - V2X: physics-only L1-L3, VeReMi.
  - **LiDAR: INTERIM, label-free L1 geometry union only.** The supervised v2-baseline XGB is excluded: it caused most of the S3 false alarms.
- **Cross-domain (WP6 S1-S2b):**
  - Motion witnesses from GPS/IMU, LiDAR odometry and CAN wheel speed (KITTI with simulated CAN; comma2k19 with real CAN + GNSS + IMU).
  - Pairwise |z| residuals, leave-one-group-out thresholds, and a minimum-vertex-cover blame ("which domain lies") at domain level. No CAN glitch filter.
- **Fusion (fusion/system.py M2System):**
  - Per-entry density transform: V2X tick max of k heard messages -> G(M)^k. Network: none, because flows of one minute are not independent.
  - Per-entry ECDF on clean validation ticks.
  - Log-form noisy-or (label-free, chosen on validation over max).
  - System threshold = tie-safe 2% of the pooled out-of-fold clean composite scores (leave-one-group-fold-out over 3 folds of drives / captures / routes / time blocks).
- **Temporal correlator (fusion/correlator.py; v2 correlator logic re-written, v2 windowing retired):**
  - An alert EVENT opens on 2 alarm ticks in 5 s, or on 2 domains with their own alarm in the same tick. Alarms within 15 s merge.
  - Event fields: start, end, domains, blamed domain, explanation.
- **Response policy (fixed a priori):**
  - LOG: alarm ticks outside events. WARN: every event.
  - DEGRADE: the blamed domain has >= 3 blamed ticks. Its trust is lowered: GPS -> odometry fallback, CAN speed -> GNSS/IMU, V2X -> drop the messages, network -> isolate the host.
  - SAFE_STOP recommendation: >= 2 motion-critical domains degraded, or a motion-critical degrade lasting >= 30 s. V2X / network alone never go above DEGRADE.
- **Frozen for WP7:** `results/WP6/m2_system.pkl` (`fusion.system.load_m2()` -> {"K": 6 entries, "C": 4 entries}) and `m2_system.json` (config).

## 2 Evaluation data (the main limit)
**No public dataset has all five domains on one car.** Every result is therefore on composite drives: each domain's own test stream is placed on a common 1 Hz clock.
- Family **K** = one KITTI run (GPS domain + cross + LiDAR of the same drive, 8-45 s; median clean composite 16 s) + ROAD CAN + the D10 one-host network view + a
  VeReMi ego view (300 m).
- Family **C** = one comma2k19 120 s window (cross only) + the same CAN / network / V2X.
- Exactly one domain is attacked per composite, plus coordinated GPS+CAN scenarios.
- Cross-domain correlations between domains are therefore *constructed*, except inside the vehicle block (GPS / IMU / LiDAR / CAN speed of the same car).
- V2AIX (real CAM traffic with an ego GNSS pose; WP5 S0c/S3b) will add the first real V2X genuine-traffic FA and an ego V2X self-report witness. It is not in M2.
- Exposure: every domain test set was scored before (ROAD >= 6x, D10 several, VeReMi 2x, KITTI several, comma 2x). The fusion test composites were scored in S3, S4
  and S5 (third exposure). The M2 calibration, correlator and response were scored on test once.

- **Per attacked domain (K, event detection):** V2X 79%, CAN 69%, GPS 56%, network 44%, cross-only (LiDAR-odometry / CAN wheel spoofs) 33%, LiDAR (interim) 10%.
- **Median first-alert delay:** V2X 2 s, CAN 1-4 s, GPS 2-5 s, cross-only 3-5 s, network 2-11 s. Network Evidence is up to ~5 min late in the streaming runtime
  (WP7 S1b), so the network delays are optimistic.
- **Response per scenario:**
  - V2X 80-92% DEGRADE. CAN signal attacks 56-89% DEGRADE.

  - Coordinated GPS+CAN reaches SAFE_STOP in 18% (K) / 83% (C, gnss_can).
- **Ablation (K, event detection):**
  - Without v2x 32.1%, without can 50.3%, without gps 64.5%, without network 63.6%, without cross 60.4%.

- **History of the clean tick FA, K / C:** S3 6.36 / 6.31%; S4 2.73 / 4.78% (supervised LiDAR removed); S5 2.08 / 6.70%.
- **v2 (NOT like-for-like):** v2 live simulation 1.90% FA per row, 84.2% recall per row. v2 used a supervised meta-classifier on the tested classes, long attack blocks

## 4 What cross-domain adds
- **Detection that no single domain has.** These are physically consistent spoofs of one motion sensor (LiDAR odometry scale / bias, CAN wheel-speed scale / offset /
  freeze). They are seen only as inconsistency between witnesses. With cross the K vehicle-block families reach 43.6%, without it 19.0% (+24.7 points). GPS spoofs gain
  +19 to +32 points; coordinated GPS+CAN 55% vs 25%. On comma (real CAN + GNSS) the gain is +51 points.
- **Blame.** When the inconsistency is decided, it names the lying sensor. S2b: comma CAN spoofs blamed on CAN in 100% of cases; wrong blame 1.4-3.4%.
- **Limits.**
  - With only two speed witnesses, GNSS attacks stay "undecided" at domain level.
  - The event-level rule lets a single noisy decided tick pin the event on another domain: comma GNSS attacks are 0% correctly blamed, KITTI cross-only families 4-50%.
  - A coordinated GPS+CAN attack is blamed on the honest witness (predicted in S2).
  - Under one shared 2% budget the weak-signal domains lose detection. At equal FA, fused vs alone: CAN 81 vs 100, cross 39 vs 69, GPS 61 vs 74; network gains (53 vs 19).

## 5 What is NOT met (stated plainly)
1. **False alarms do not transfer from validation to test.** Validation held-out FA was 2.15% (K) / 2.04% (C); test is 2.08% / 6.70%. Every domain's clean test ticks
   score higher than validation (e.g. CAN share above the 0.99 level 1.0 -> 3.6%). The validation pools are small: 3 KITTI drives, 10 ROAD clean captures, 17 comma routes.
2. **25-31 alert events per clean hour** (target <= 10; validation 8.2). This is far from deployable: a real vehicle needs well under one per hour.
3. **Safe-stop recommendations: 1.23 per clean hour on C.** Long ROAD CAN false alarms trigger the >= 30 s rule. A safe-stop should probably need a second domain.
4. **Detection 60% (K) at this FA, and held-out types 59%** (rules 70% / 60%). LiDAR (interim) and cross-only families are weak. Web-XSS 11%, PointDrop 8%.
5. **Blame wrong in 13% of detected events** (rule <= 10%): see section 4.
6. LiDAR is INTERIM. Single-return phantoms are not evaluated at system level (WP3 S9). An M2 addendum re-runs fusion when M1-LiDAR closes.

## 6 Corrected thesis claim
The claim **"physics is the zero-day defence"** is not supported. The claim the data support is: **physics / rule layers and normal-only models are complementary.**
- S4, held-out types, K system: rules-only 36.9%, normal-only L3 56.6%, both 69.1%.
- The rules miss exactly the attacks built to pass them: CAN masquerade 0% (tick level), GPS Doppler / meaconing 39% vs 72% for the EKF / L3.
- The normal-only models add value only where normal behaviour is well modelled: CAN signals, V2X Kalman, GPS EKF.
- Cross-domain physics adds a second, independent kind of evidence for motion-sensor spoofs (section 4). It does not lower the false-alarm problem.
- The evidence-novelty layer was dropped: it cost held-out detection (-8 points).
