# WP8: v3.1, targeted improvements evaluated on fresh hold-out data

Branch `v3.1` (v3 frozen at git tag `v3.0`; never move or rewrite the tag). v3 numbers in
RESULTS_v3.md stay as they are; v3.1 writes its own results to `results/WP8/` and its own
summary to `RESULTS_v31.md`.

## Goal

Raise v3 where it is weak, honestly: tune on validation only, then score ONCE on hold-out
material that v3 never scored (`H31`). If no fresh material exists for a domain, that domain's
v3.1 number is labelled "re-used test (exposure n+1)" and cannot be called an improvement.

Weak spots (from reports/M3.md, WP7_S2.md, M2.md):
1. System false alarms on clean driving: 3.31% K / 6.15% C (bound 3%); 18.4 / 27.5 events per
   clean hour (bound 10); SAFE_STOP 1.64/h on C (bound 1).
2. Mean event detection 60.8% (target 70%).
3. LiDAR: PointDrop 87% alone but 27.6% inside the stack; 1.98 s per scan (~19x too slow).
4. Network: 5-minute bins: Evidence 66 s late (median), 242 s max; unseen Bot 0%.
5. CAN: window cost grows 0.14 s -> 2.3 s on long captures.
6. V2X: runtime only validated for the whole-block stream, not for one ego (~7 msg/s).
7. Blame: KITTI gps_can blamed on the honest sensor 70%; comma GNSS spoofs blamed on the wrong domain.

Known physics limits (do not try to "fix"; state them): calibrated LiDAR phantoms invisible to
single-return physics.

## Crash safety (binding for every WP8 worker; the machine or the usage limit can stop you any minute)

1. Journal: append one line to `notes/WP8_journal.md` (`<ISO time> | S<k> | <what> | <state/next>`)
   at start, before and after every run longer than 2 minutes, at every decision, at the end.
   Write the line BEFORE starting the action.
2. Long runs: resumable scripts (per-chunk outputs in results/WP8/<step>/parts/, skip chunks
   already written, write to a temp name then rename); launch in the background with a log file
   in results/WP8/logs/; record the command and log path in the journal.
3. Commit your own files after every finished sub-task (at most ~30 min of uncommitted work);
   never commit data or V2AIX-derived per-message files.
4. Resume: a worker that starts a step first reads the tail of notes/WP8_journal.md and the
   files on disk, and continues; never redo finished chunks.
5. Brief: keep `notes/WP8_brief.md` (<= 60 lines) current at the end of every sub-task.
6. Keep scores (orchestrator 2026-11-03, after P1 found v3 per-sample scores lost with the deleted caches):
   every scoring run (validation and H31) saves per-sample / per-window / per-tick scores and labels
   to `results/WP8/scores/<step>/<domain>_<split>.npz` (or .parquet). Never under a cache folder,
   never deleted. Commit if < 50 MB; else keep on disk and list path + sha256 in the report.
   No V2AIX per-message files are committed. S7 uses these to draw the curves P1 could not.
